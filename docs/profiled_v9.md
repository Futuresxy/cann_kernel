# V9：削减 Device 频率初始化并分开编译计算路径

本轮基线为 V8 `c9dd01c9…`，使用同一 runner、同一输入、同一 GM 分配的双顺序 profiling 比较。固定 33 点单独作为性能代表集，不把新增小形状混入主要平均值。V4 的 Host 频率表按补充规则只保留为历史精度对照。

最终源码 SHA256 为 `5917d3aaeb6969619852ba56cc7934f5bae66540295cf381fc0340bc50529ecc`，1889 行、89328 字节，首尾标记为 `ROPE1743_PROFILED_V9`、`END_ROPE1743_V9`。平台隐藏 15 点尚未提交 V9，本文数字仅代表本地测试。

## Profiling 决定的优化顺序

V8 tiny 每核 scalar 时间约 2.11us、VEC 约 0.41us，标量占比约 80%；D1024 多 head 路径 VEC 占比约 86%。因此先削减频率初始化，再独立尝试宽维向量计算。流式 FP16 的本地最小读写量为 1GiB，原耗时约 844us，已经对应约 1.27TB/s 的有效数据流量；初始化微调无法让这个场景产生数倍加速。

保留的改动如下：

1. 短频率向量先用通用 exp2 多项式求值，以误差区间判断 FP32 舍入是否确定。确定时直接得到相同 FP32 power；不确定时才在当前 kernel 内生成五个通用 exp2 根幂，并使用 Q53 保护位路径。省去原来每核无条件生成的 32 项数学小表。根幂索引为零时直接使用数学单位元，不读取尚未生成的工作区。
2. 相同的已舍入 power 在本次频率生成循环内复用 reciprocal，减少重复的整数除法。每个指数和 power 仍由当前 theta 计算；局部状态在每次函数调用初始化，没有跨调用缓存。小自变量使用受同一误差界覆盖的线性求值。
3. 半维为二的幂时，`i/width` 用精确二进制缩放生成，省去通用向量除法的补偿流程。其他宽度继续走原补偿算法。
4. 标量频率工作区按五个 uint64 根幂的实际需要缩减，最低申请量从 256B 降为 64B。对齐、宽维和 FP32 直接计算路径将第一次输入 DMA 移到频率初始化之前，利用独立缓冲重叠执行；完成屏障仍在读取输入和频率之前。
5. 用不同的频率配置类型实例化 scalar/vector 内核。每次调用只选择一个实例并启动一次。向量实例不再携带完整标量分支，标量实例也不再携带宽向量初始化图。D1024 FP16 向量 entry 的未重定位 text 从混合版本的 24160 字节缩到 17060 字节，标量 entry 为 11096 字节。这里记录的是代码尺寸；没有把未测量的寄存器溢出或 I-cache 原因写成定论。

正余弦和旋转保持原 FP32 路径。位置为零时保持输入位模式。Host 只读取 shape/dtype 等元数据、选择算法和 tile/core 数、传入 theta 标量并启动一个分支；不读取或重排输入张量，不生成任何频率向量。

最终 PMU 诊断中，tiny 每核 scalar 约 1.625us，原 V8 对照约 2.113us，VEC 均约 0.41us，支持初始化成本下降这一解释。D1024 FP16 最终 VEC 仍约 26.34us、占比约 85.6%，说明主向量循环还有优化空间。PMU 使用 replay，不用于前述正式加速比；源文件、二进制哈希和原始 CSV 随记录保存。

## 数学误差界与新增精度修复

通用 exp2 七阶插值多项式定义在 `[-1/2,1/2]`，系数是数值算法常数，不是 RoPE 结果。插值余项界乘以 Q31 尺度小于 0.123；加上系数舍入、Horner 截断、log/product 截断、归一化和原 Q53 保护路径的误差，合并界约为 10.666 个 Q31 单位，采用 16 单位保护范围。只有误差区间不触及 FP32 舍入中点时才接受快速求值。

`numerical_model/coefficients.py` 可重新生成系数和误差界。`lazy.py` 比较 625328 个频率，快速接受 545965 个，与原保护位标量算法没有位差；另对 theta 接近 1、宽度直至 512 的 20900 个频率检查也没有位差。根幂树与原递推表的最大差为 1 个 Q61 单位。CPU 数值模型是补充证据，设备参考校验仍独立执行。原保护路径的范围缩减参考 [Arm exp2f](https://raw.githubusercontent.com/ARM-software/optimized-routines/master/math/exp2f.c)。

新增 640 项 theta/shape 测试发现 V8 原有问题：theta 为紧邻 1 的较小 FP32 数时，宽维双浮点近似不能稳定判定部分 power 的舍入中点。V8 对照通过 630/640，失败项最大误差约 0.28–0.68。新版本对非零 `log(theta)` 极接近零的数值区间使用整数保护位算法；exact theta=1 继续使用原本正确的向量算法。分派依据数值条件和公开参数，不匹配测试编号、不存储预计算结果。

这个保护区间可能增加较宽维度的初始化成本。消除重复除法后，一组 D1024、theta 紧邻 1 的本地 event 记录，在最终版本约为 27.00–27.12us；普通 V8 在其中一个边界上输出错误，不能把它的较快耗时当成有效优化目标。event 数字只用于说明额外成本，不与无 replay profiler 的正式性能指标混算。

为验证模板类型确实穿过所有分派，还增加 192 项 theta 接近 1 的测试，交叉覆盖多 head、单 head 合批、长序列和非对齐路径。精度阈值、99%比例和最大绝对误差条件均保持赛题原值。

## 失败候选及取舍

| 候选 | 实测反馈与决定 |
|---|---|
| 固定循环展开 | 部分指令布局改变，没有独立稳定收益，保留为数值等价控制 |
| 三段 uint32 精确倒数 | 穷举全部 8388608 个规格化尾数，结果相同；没有性能收益，未合入 |
| 余弦多项式替换 sqrt | 51/52 通过，FP16 大幅值用例最大误差 4.0 超过 0.1；淘汰 |
| 宽维两读 Mul/Add 替换三读乘加 | 目标 D1024 FP16 在探索对照中回退约 18%；淘汰 |
| 完整表外高阶 exp2 | CPU 检查发现少量舍入不同，未作为提交路径；改用保留原保护路径的快速求值 |
| 混合 entry 中增加标量复用 | 小输入改善，但部分宽维 entry 回退；通过独立编译实例保留收益 |

[Ascend C 复合计算说明](https://asc.gitcode.com/api/SIMD-API/basic_api/memory_vector_compute/composite_compute/overview.html)提示三个独立操作数可能影响读端口吞吐，因此尝试了两读替换；本机数据否决了该方案，未以理论吞吐替代实测。所有候选补丁、源码哈希和结果位于 `benchmarks/experiments/round8/`。

一次六进程初筛在最后一个、已因精度失败淘汰的 cosine 候选上触及 60 秒设备预约上限。仅使用前五份完整且计数正确的初筛记录，没有接受不完整采集。早期 V9 候选的验证保存在 `pre_typed_validation/`，最终验收按最终源码重新执行。

## 最终验收与固定性能集

最终普通/audit 二进制均绑定上述源码。3988 项参考精度检查全部通过：基础 52、原数学矩阵 256、小输入 544、新 theta 矩阵 640、跨分派 192、偶数 D 扫描 1010、packed 456、路径扫描 672、额外对齐 166。逐次审计 8028 次 runtime launch，均为每调用一个 kernel；独立 profiler 为 75 次调用、75 个 device task。414 项 V4 直接比较无新增输出位差，逐位一致只作额外诊断，赛题原误差阈值始终独立执行。

固定 33 点 ABBA+BAAB 完整导出 2640/2640 个 device task，几何平均加速 **1.030×**。每个实现各有 4 个采样块中位数。原始结果为 `benchmarks/results/profiled_v9_balanced.json`；不存在隐藏点对应关系。

| 场景 | V8 / us | V9 / us | 加速比 |
|---|---:|---:|---:|
| tiny | 3.050 | 2.650 | 1.151× |
| unaligned_half | 5.370 | 5.070 | 1.059× |
| deepseek_half | 18.130 | 17.510 | 1.035× |
| short_s16_h32 | 7.861 | 6.880 | 1.143× |
| prefill_h32_d1024_half | 32.690 | 31.971 | 1.022× |
| prefill_h32_d1024_float | 34.311 | 33.101 | 1.037× |
| large_stream_half | 843.497 | 842.786 | 1.001× |

三个微小回退也保留：D96 FP16 15.880→15.920us、D192 FP16 20.590→20.660us、非对齐 D254 FP32 153.603→154.293us。没有宣称所有 shape 都变快。大流式输入基本持平，本轮没有解决其主要执行成本。



补充 105 点双顺序采集为 8400/8400 个 device task，合并几何平均 1.054×；其中新增 72 点为 1.065×。这两项作为覆盖数据单独记录，不替代固定 33 点的主要结论。完整数据位于 `profiled_v9_extended_balanced.json`。

## 复现及提交范围

```bash
python3 tools/replay_experiment.py final --round round8 --source-only
bash tools/build.sh
bash tools/build_launch_audit.sh
bash tools/validate_profiled_v9.sh --phase prepare
for phase in correctness math small new_math dispatch sweep packed_sweep path_sweep aligned_audit precision; do
  task-submit --device auto --timeout 0 --max-time 60 \
    --run "bash tools/validate_profiled_v9.sh --phase $phase"
done
```

各设备任务串行申请一张卡、完成即释放，每次预约不超过 60 秒。编译、数据准备和报告在 CPU 完成。频率、角度、正余弦和旋转始终在当次唯一 Device kernel 内计算；没有 Host 结果表、跨轮缓存、空 kernel 或计时识别。

正式 payload 只替换 `kernel.asc`；源码哈希、Git 提交、普通/audit 二进制、精度结果和设备任务计数共同绑定。原模板其余 7 文件必须逐字节一致。平台得分需要由 Mac 上真实提交的 15 点结果确认。
