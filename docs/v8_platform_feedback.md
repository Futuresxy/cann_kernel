# V8 平台反馈复盘

结论：这次没有形成明显的平台收益。以前述以 3.26、5.03、6.29us 开头的历史 V4 对照序列计算，V8 的等权几何平均时延高 5.61%；对 V7 则只低 0.52%。这是时延对比指标，不是平台官方得分。前 7 点相对历史序列全部回退，第 11、12、13、14、15 点仍有不同程度改善。

用户反馈没有导出上传源码哈希、隐藏 shape、平台 profiler 或硬件信息。本文按 V8 后续反馈关联版本；不把隐藏编号映射为本地 shape，也不把某个点的变化直接归因于未经观测的 kernel 分支。原始记录与计算在 `benchmarks/results/platform_user_v8_20261016.json`、`benchmarks/analysis/v8_platform_feedback.json`。

## 主因一：Device 频率初始化开销仍然很高

Git `0a4281f` 的 V4 在 Host 执行 `1/std::pow(theta, exponent)`，并将频率向量、宽维修正值作为参数传入 Device。V7/V8 按补充规则移除了这部分 Host 计算。旧 V4 不能直接回退作为符合现行规则的提交版。对只统计 Device task 的 profiling，旧 Host 频率计算不计入这段 Device 时间；受保护的平台 judge 没有公开完整计时实现，不额外假定其所有计时细节。

当前 `ScalarFrequencies` 仍然每核、每调用完整执行：

1. Q53 log2 的串行整数级数及除法；
2. Q61 通用 exp2 表的级数生成和 32 项递推；
3. 每列 power 计算，含 Q31 检查和必要的 Q53 回退；
4. 最终 FP32 reciprocal 的整数舍入和 UB 写入。

V8 的 Q31 优化主要缩短第 3 步。log2、建表、最终 reciprocal，以及各个 AIV 核重复初始化的结构都保留。源代码入口为 `operators/rotary_pos_emb/kernel.asc:354`。宽向量则沿用高低位运算图，包含二百多次向量 API 调用；这也不是轻量的初始化。

已有 PMU 的 tiny 样例中，V8 每核 scalar 时间约 2.100us、VEC 约 0.410us，scalar 占比约 80%。V7 对应 scalar 约 2.173us。这里只削减约 0.073us 标量时间，没有解决主要成本。PMU 比例可能重叠，不能把各流水线时长相加当成总时长。

这是源码和本地 PMU 确认的瓶颈，与平台低延迟点的回退方向一致。由于隐藏 shape 未知，它还不是逐个隐藏点的直接诊断。

## 主因二：优化覆盖范围与本地平均指标不匹配

V8 新拆列路径只在 token 数小于 128、D 不超过 256、工作集不超过 2MiB、行任务数不超过可用 AIV 核数四分之一，并满足列搬运/分区条件时启用。对应 Host 分派从 `kernel.asc:1615` 开始。

按实测 48 AIV 核重放这些公开参数条件：

| 本地性能组 | 点数 | 几何平均加速比 |
|---|---:|---:|
| 原有性能矩阵 | 33 | 1.024× |
| 新增的小形状矩阵 | 72 | 1.159× |
| 两者合并 | 105 | 1.115× |

新拆列路径命中 28/105 点，其中 27 点来自新增矩阵，原有 33 点只命中 `single_token_many_heads` 这 1 点。它在特定低并行度形状上确实有效，例如 `[1,1,256,128] / float16` 从 8.65 降至 5.77us；但不足以覆盖一般的小输入，更不能推断隐藏测试点会采用同样分派。

因此上轮将 1.115× 作为主要性能结论不够合适。105 点采集是真实、可复现的，但新增形状的数量使总体指标偏向了这次优化覆盖的场景。后续需要保留固定代表集单独比较，并按 token/head/dim、dtype、对齐、并行度分桶；不能不断增加有收益的形状再用混合平均值代表整体进步。

## 主因三：大输入主计算没有发生明显变化

V8 沿用 V7 的大输入搬运、正余弦和四乘两加减旋转路径。长序列或较宽维度通常不能进入新增拆列分支，因此不应期待初始化微调显著改善数百 us/ms 的运行时间。

本地 `[1,256,32,1024] / float16` 为 32.540→32.531us，流式 FP16 为 844.327→843.247us，均基本持平。宽维 PMU 的 VEC 占比约 86%，表明还需要研究正余弦/广播/旋转向量指令；流式路径的访存问题则要独立采集和分析。不能仅因平台第 10 点是 ms 就断言其为某个大张量或纯带宽瓶颈。

## 开发约束也需要调整

414 项与 V4 输出逐位相同是本地额外增加的门槛，不是赛题要求。它有助于发现数值回退，但一旦把任何位变化都当成失败，就会排除满足赛题误差阈值的融合计算和其他数学实现。后续应以原赛题全部误差条件为硬门槛，以 V4 位差作为诊断；特殊值、零位置原始位模式、最大位置和近消去测试继续保留。这个调整不意味着放宽比赛的精度阈值。

也不能直接切回普通 FP32 Ln/Exp：之前实验只通过 16/52 项，大位置会放大频率误差。需要先证明频率误差如何传到最终输出，再决定算法，而不是无条件降低精度。

## 下一轮优先级

1. 先解决每核 Device 频率初始化：分别测 log2、建表、power/reciprocal 的串行成本，目标是减少整个初始化依赖链，而不只优化其中一个多项式。
2. 用原有固定 33 点、公开样例和新矩阵分桶分别验收。候选必须在原有代表集显示稳定收益，并列出最差回退；新矩阵用于覆盖边界，不能替代基线代表集。
3. 独立优化较宽/较大输入的向量主循环和搬运重叠。按 profiler 的 VEC、scalar、MTE 指标决定方向；不把小输入的拆列阈值直接扩大到所有输入。
4. 全流程继续放在当次唯一 kernel 内，Host 只做参数、分块和启动；没有外部结果表、跨轮缓存或按隐藏编号编写的分支。

本次只归档反馈和分析，kernel、提交包及 ready 源码哈希均保持 V8。本次分析复用已有源码、真实 PMU 与双顺序采集，没有预约或占用 NPU。
