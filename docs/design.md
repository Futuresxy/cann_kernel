# 实现与硬件映射

输入、输出和 `run_kernel` ABI 与附件一致。只接受赛题要求的连续 ND float16/float32 与 int32 positions；位置由设备读取，host 不读取或特化任何输入数据。

## 按形状选择执行路径（PROFILED_V5）

- 对齐、多 head、小中维度：dim 为16倍数且小于512，整行连续 DMA，输入输出双缓冲。每核批量生成最多16个 token 的 FP32 cos/sin，保存在 UB 中，供本核后续 token/head tile 使用。repeat stride=0 广播频率，两个 Mul 和两个 MulAddDst 完成旋转。
- 对齐、dim≥512：扩大 tile，输入双缓冲、输出单缓冲，两个 FP32 工作区之间增加32字节间隔。输出缓冲在计算末尾分配。频率恢复在向量流水执行，减少宽维度初始化的 scalar 工作。该布局在中小维度没有收益，未推广到全部形状。
- FP16多 head：dim为32倍数、heads≥16、tokens≥128时，在FP32生成三角函数后，将系数转换为FP16并进行输入精度的旋转。直接在输出队列计算，消除整个输入tile的FP32转换与结果回转，最大tile16384元素、head tile上限128。小shape和FP32输入保留原路径。
- 单 head：所有对齐dim（含513..1024）在tokens≥16时按UB预算合批。改用两个FP32工作区及两个Mul/两个MulAddDst。宽维度使用WideFrequencies，不增加启动。
- 单 head、小维度：dim≤128、tokens≥128时，positions也按块装载；int32→FP32后用Brcb和规则Copy广播，再与频率相乘。先产生position=0掩码，在输出阶段Select原始输入位模式，省去逐token的GM标量读和零位置分支。
- 非对齐、多 head：dim≤64、heads>32、tokens≥128时按head分块连续装载整行，再在UB中Gather分离和重组；head tile以2048个半维元素为预算。更宽维度的重排成本较高，保留通用路径。
- 非对齐小维度：dim≤128、heads≤32、tokens≥128，整块连续 DMA，UB 中 Gather 分离/重组前后半维，紧凑 cos/sin 通过索引广播到各 head。也用于 dim=16、2≤heads≤8 的长序列。索引在当前 kernel 的 Init 中生成；不读取 host 输入、不跨调用缓存数据。混合零位置用位掩码 Select 恢复原始输入位模式。
- 通用：其他偶数维度用 DataCopyPad 分别装载前后半维，每行填充到16个元素的倍数。GM stride 使用字节，UB stride 使用32字节块，输出只写有效元素。

对齐连续路径的单个输入张量≥128MiB时，仅对输出设置L2 bypass，保留输入缓存；切换依据是当前调用的真实shape/dtype。没有缓存旧计算结果，也没有假设下一次输入相同。该策略在重复输入的稳态测试中收益较大，冷输入收益可能不同。

所有分支均在一次 kernel 启动内完成。只根据公开的 shape/dtype 选择路径，不推断平台测试序号。

宽维度的512个FP32频率不能直接放入默认1536字节的kernel参数区。`WideFrequencies`保存128个FP32种子、3个FP32比例和384个int16 ULP修正值，总计1292字节。host先独立计算每个频率，再记录它与种子乘比例所得FP32值的位模式差；设备端乘法后应用整数修正，恢复对应FP32频率。修正值用于无损编码，不把频率降为FP16。全部角度、cos/sin与旋转仍在同一个kernel中完成。

## 精度路径

1. 频率在算子 host 入口以 `1.0f / pow(float(theta),float(2*i)/dim)` 计算。严格跟随附件 NumPy FP32 的除法/幂/倒数次序，避免使用 exp(log(theta)*...) 引入长位置下频率误差。
2. 频率作为算子自身的launch参数传入，不改变接口、无外部 cos/sin、无固定shape或输入输出预计算表。
3. 位置转换为FP32，FP32乘法得到与参考相同舍入的角度。
4. 使用 `2π = 6.25 + 0.033203125 - 0.000017817820413523074` 三段缩减。对于赛题位置范围和常用theta≥1，前两项乘法可以避免大角度直接相减损失。
5. 缩减后的角度除以4，在[-π/4,π/4]使用9阶sin多项式。由正平方根恢复cos，再使用两次二倍角公式恢复原角度的sin/cos。所有步骤均为FP32。
6. FP32旋转及通用FP16路径保持FP32乘加；符合上述条件的FP16多head路径将FP32 cos/sin转换为FP16后进行旋转，符合赛题允许旋转乘法使用输入精度的规则。频率、角度与三角函数生成仍为FP32。所有输出按原赛题容差判断，不放宽阈值。
7. position=0直接复制输入。通用路径补充MTE2→MTE3同步；对齐和合批路径经过VEC输出队列，保证跨流水线依赖。

`run_kernel`每条分支只调用一个kernel，宽维度分支启动后立即返回。测试runner用链接器包装实际`aclrtLaunchKernelWithHostArgs`接口，逐次检查启动数；另用非replay的msprof设备任务记录校验75次调用恰有75个AI_VECTOR_CORE任务。测试包装器不进入提交文件。

官方高阶 Sin 的输入范围和临时空间约束见[华为 Sin API](https://www.hiascend.com/document/detail/en/canncommercial/850/API/ascendcopapi/atlasascendc_api_07_0500.html)。本实现使用融合三角函数路径，并以实际设备误差与PMU指标验收。

## UB预算与分块（含V4保留路径）

对齐小中维度：输入/输出各两个 tile，加三个 FP32 工作区，剩余 UB 用于频率与三份跨 token 三角函数缓存；缓存批量上限同时受188KiB预算、工作区大小和本核有效 token 区间限制。典型 FP16 D=64/H=128 输入/输出65536字节、工作区98304字节、频率与16个 token 缓存6272字节，共170112字节。

大维度路径用三个输入/输出 tile 和两个带32字节间隔的 FP32 工作区；FP32 tile 最多8192元素，FP16最多12288元素，再按同样的188KiB上限计算 trig 缓存。非对齐连续路径的 pair 容量不超过2048，六个 FP32 工作区、五份 uint32 索引、四个双半维输入/输出 tile、频率与掩码合计低于192KiB。每个队列/缓冲均按 CANN 要求对齐。

FP16原精度旋转的UB公式为 `8*size + 26*cacheSize + 4*freqSize` 字节：四个FP16输入/输出tile、两份FP32三角函数scratch、三份FP32/三份FP16缓存。批量数按188KiB预算向下取整，D1024的最大配置约186368字节。单head路径采用 `30*size`（FP32）或`22*size`（FP16）字节的主预算，再预留频率/位置队列/掩码空间；小维度bulk路径将token tile向下对齐到8。

全局偏移和总任务数使用64位整数。每核按连续任务区间分工，保留同token复用；核数取可用AIV数与任务数的较小值。全部本地验证只申请一张卡。

## 性能判据

保留改动需同时满足：精度通过、边界哨兵完整、原生延迟改善、profile指标支持预期。使用Task Duration评价kernel执行，使用ACL event记录原生批次平均时间，同时保留host时间；不把profiling replay过程中的event结果用于性能对比。

本轮新增 FP16 极大幅度压力测试暴露旧版已有的数值限制：scale=60000、最大位置下，近似三角函数与 FP32 乘加的舍入差异可能跨过 FP16 量化边界，导致单个元素差32，超过赛题最大绝对误差阈值。该诊断有独立固定种子和失败记录，不能据常规集通过声称覆盖所有 FP16 数值，详见 profiled_v4.md。

V5按用户要求将极大幅度压力点保留为诊断，不作为本轮优化的阻塞项。正常数值的参考阈值未改；新增路径另有672项扫描。完整实验记录见profiled_v5.md。
