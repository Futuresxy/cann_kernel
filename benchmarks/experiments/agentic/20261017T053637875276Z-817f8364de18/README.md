本轮结论：保留非对齐 FP16 的局部收益证据，拒绝将同一布局整体推广到 FP32。只归档一个实验源码，没有发布 ready、修改 latest 指针或操作平台浏览器。

请求为 `20261017T053637875276Z-817f8364de18`。基线是提交883390实际通过15项、官方48.78分的归档源码817f8364；不是仍保留在正式 operators 目录的 V9 5917d3aa。实验源码 SHA256 为 `d65529a298114f522b3fbfa4f405670af1c98c0fb32a9648562043c7ea03b168`。源码、补丁、二进制及冻结输入哈希绑定在本目录和上级同名 JSON 中。

这项实验来自源代码数据流和补缺 PMU：通用 Rotary 在每个新 token 上将两组系数各复制到 tileHeads-1 行，并在第一半输出覆盖输入后重新转换第一半输入。此前宽泛 Gather/连续搬运、CopyRotary、wide two_read、mask_trig/mask_all 的结论已审阅，见 [工作量与旧实验模型](pre_experiment_model.json)。本轮不使用 Gather、不改 DMA/队列、不改 trig、frequency、dispatch 或算术顺序。

令 N=B*S、K=D/2、e=输入元素字节数。数学旋转量为3*N*H*D FLOPs，最低逻辑 X/Y 流量为2*N*H*D*e；FP16/FP32 的旋转算术强度分别为0.75/0.375 FLOP/B，尚未包含频率、trig、转换和控制，不能据此断言 DRAM 限制。每核独立生成 K 个频率；同一 token 的系数只在该次调用内复用。

两个补缺代表均为 N1024/H64、tileHeads32、2个head组、2048个job，48核各42或43个job。核边界使总计访问1040次token，理想为1024。D126/FP16 的 pitch64、逻辑X/Y约33.03MB；D254/FP32 的 pitch128、约133.17MB。原路径每job两次半行装载、两次半行写回，job末尾 PIPE_ALL，输入/输出队列均为1。本轮保持这些条件，所以搬运和同步的成本下界没有消失。

实验将5个cap工作区改为原输入a/b、结果lo/hi、交叉乘积tmp；紧凑c/s移到频率缓冲尾部。先完成trig再装载a/b，两半输出生成前不覆盖a/b；tmp在交叉项被使用后才覆盖，各列及各行互不重叠。仍是原来的4个分离FP32乘积及Sub/Add，最终转换相同，position0保留原位模式。完整UB公式和全部合法D/H的容量枚举见模型：上界FP16 120832B、FP32 153600B，低于192KiB。这里为了保守也枚举了不会由当前dispatch到达的对齐几何。

预期减少每新token的62次系数复制及每job的一次半输入Cast/DataCopy。两个代表共移除64480次源级系数DataCopy调用；FP16/FP32各少转换或复制约419万/839万个半输入元素。广播仍需要同样的旋转元素工作。count API 本来就使用硬件repeat，不能把192/384个repeat体误当192/384条独立指令，也不能把广播API数量当汇编指令收益。

原生非replay Task Duration使用相同冻结输入、同一进程内相同分配/地址、ABBA和交换源码后的BAAB；每种源码取4个block中位数的中位数：

| D126/H64/FP16 | 108.412 | 98.592 | 1.0996x | -9.06% |

FP16在两种源码顺序中均受益，FP32在两种顺序中均回退。完整33点几何平均只有1.001942x，不能据此推荐整体替换或预测官方分数。完整计数2640次调用、2640个设备任务；两次进程各自上下文/地址共享，进程之间不宣称地址相同。未改动entry的部分控制点也有波动，因此不把控制点的表观变化算作新布局收益。所有33点最终输出完整字节相同，见 [配对分析](native_analysis.json) 和 [输出比较](fixed33_output_bit_comparison.json)。
